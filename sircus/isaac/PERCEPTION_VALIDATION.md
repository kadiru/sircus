# Randomized perception validation

This is a **frozen-detector, static observation study**, not RL training or a
bounce/capture benchmark. The estimator is unchanged from the first RGB-D baseline.
Scene ground truth, planned geometry and visibility labels remain evaluation-only.
No physical or Viam resources are used.

## Prespecified final study

Contract `sircus-perception-validation-v3`, seed `20261031`, 24 layouts × six
paired conditions = 144 observations. Each layout uses identical geometry across
conditions. Ball placements are balanced: six above board, six between board and
bucket, six on the table, six inside the bucket. These are held static for capture,
not sampled from a trajectory. Lighting captures wait 24 render updates after each change. Noise-only variants reuse the exact clean RGB/depth capture; combined noise reuses the warm-light capture. Camera calibration and truth are copied from that same source observation.
The ball is repositioned every physics substep; this study makes no contact claim.

Board layouts are generated by independent ±0.08rad perturbations of all six board
arm joints around the existing pose. Manufacturer FK predicts the board location;
actual articulation state supplies evaluation truth after settling. Joint-limit
and board-height violations are excluded and reported without resampling. This
samples a neighborhood of the existing configuration, not the entire reachable
workspace. The board is not required to face the bucket for perception testing.
The dropper remains at its initial configuration.

Bucket XY is sampled uniformly from X[0.45,0.87]m, Y[-0.64,-0.34]m. The fixed camera,
object sizes and materials remain unchanged. All units are SI. Bucket reported
height 175 mm remains ambiguous; provisional interior 175 mm/base 8mm is preserved.

| Condition | Dome intensity | RGB tint | Axial Gaussian sigma | Independent dropout |
|---|---:|---|---:|---:|
| clean | 500 | .85,.9,1 | 0 | 0 |
| dim_warm | 150 | 1,.7,.45 | 0 | 0 |
| bright_cool | 900 | .6,.8,1 | 0 | 0 |
| noise_2mm | 500 | .85,.9,1 | 2mm | 1% |
| noise_8mm | 500 | .85,.9,1 | 8mm | 10% |
| combined | 150 | 1,.7,.45 | 8mm | 10% |

Noise is added only to valid rendered axial depth, without filling invalid pixels.
It is reproducible by seed. This simple model is **not calibrated RealSense noise**.
Lighting uses the existing USD dome's intensity/color attributes; actual readbacks
and rendered RGB channel means are retained to verify changes. NVIDIA documents
these [light attributes](https://docs.isaacsim.omniverse.nvidia.com/latest/action_and_event_data_generation/ext_replicator-object/light.html).

## Separation and scoring

1. GPU scene writes a sensor-only NPZ with RGB/depth/calibration/frame ID/time.
2. The already-running independent CPU worker consumes only that bundle. Extra
   fields are rejected. The detector code SHA-256 is frozen and checked at end.
3. The study waits up to 10s for the exact frame ID; timeouts count as missing.
4. Actual board/ball poses and bucket/table geometry are written into a different
   directory and compared to estimates only after detection.
5. The preview shows availability and conditional errors per challenge. Missing
   detections are included in availability denominators, never assigned zero error.

The ball-visible label is independent of RGB and the detector: analytically
ray-cast the true sphere in camera coordinates and count clean-depth pixels within
5 mm of its front surface. At least 20 agreeing pixels defines visible-enough for
this evaluation. Report both detection when visible and localization within 10 mm.
This is an ideal geometric visibility rule, not manually annotated visibility;
partially occluded objects near the threshold remain a limitation. Other objects
have availability metrics, not recall. Pose errors are conditional on detection.
A table center is a visible patch, so table error is plane distance. Other errors
compare board surface center, bucket top-opening center and ball center. No truth
is substituted for missing observations. No policy consumes these estimates yet.

## Reproduce on isolated Ubuntu

```bash
# Requires the existing pinned Isaac environment/assets; no scene already running.
bash sircus/isaac/run.sh validate-perception 24 20261031
bash sircus/isaac/perception.sh status
```

The launch command starts missing CPU workers, rejects a competing scene and runs
only in `sircus_isaac_4090`. The 4070 workload remains stopped. The finite scene exits
at completion; independent CPU workers wait for future observations. Nothing starts
at boot. To stop only this Sircus scene, use `run.sh stop`; workers have their own
`perception.sh stop`. Neither command manages other workloads or hardware.

Progress and results: `output/validation.json`. Each timestamped
`output/perception-study-*/` contains the immutable plan, sensor bundles,
evaluation-only truth, estimates/overlays, per-case records and summary. These
runtime data stay outside Git. A 3GiB free-space guard prevents continued capture
when storage is low, without deleting files. After completion:

```bash
# Inside the dedicated container, replace RUN with the completed study directory.
/workspace/source/sircus/isaac/python.sh \
 /workspace/source/sircus/isaac/validation_report.py \
 --run /workspace/output/RUN --output /workspace/output
```

This independently recomputes aggregates from recorded errors, verifies lighting
readbacks, generates the availability chart and writes SHA-256 file checksums.
The existing Mac preview at port 18780 shows the results table/chart. Completed
study results remain valid historical results while the final live image ages.

## Infrastructure smoke history

A separate seed 20261032 smoke under initial Cartesian target sampling (contract v1)
excluded both attempted layouts because IK could not realize those full poses,
even with additional deterministic solver seeds. It scored zero observations and
is retained as an infrastructure diagnostic, not a perception result. Contract v2 instead sampled bounded joint perturbations. Its two-layout smoke
completed all 12 observations with no exclusions. The first full v2 pass also
completed 144 observations, but diagnostics found rendered RGB differed between
clean and supposedly noise-only observations despite matching light attributes.
This lighting-history confound is retained in its original diagnostic run.
Contract v3 reuses exact source captures for noise augmentation and verifies pixel-
identical RGB/calibration and identical truth for all 72 paired noise cases.
Detector parameters were not changed in response to these diagnostics or results.

In clean conditions, conditional mean errors were 1.99mm for the table plane,
2.21mm for board center, 3.22mm for bucket center and 3.82mm for ball center.
All 18 geometrically visible balls were within 10mm; the six inside-bucket cases
were below the visibility threshold and remained missing.

At 2mm noise, ball center error averaged 4.06mm and all 18 visible balls remained
within 10mm, but the board was never detected. With 8mm noise, only four ball
estimates remained (23.22mm mean error), and only one of the 18 visible balls was
within 10mm. Combined noise/warm light produced one ball estimate with 113.16mm
error; none were within 10mm. These outliers must not be mistaken for reliable
estimates merely because a detector reports a geometric fit.

The actual sampled board-center ranges were X[0.656,0.696], Y[-0.165,-0.057],
Z[0.324,0.449]m; bucket XY ranges were X[0.450,0.835], Y[-0.627,-0.352]m.

Priority follow-up: replace brittle color gating for the board with robust depth
plane/shape proposals, make plane extraction and fit thresholds noise-aware, and
reject uncertain ball fits. Develop on a separate seed, then evaluate a frozen
revision on a fresh held-out seed before connecting estimates to arm control.

## Remaining scope

This is one camera and one object appearance per class, with nearby board poses.
It does not validate other board shapes/colors, camera extrinsic error, motion blur,
trajectory collisions, physical grasping, or visual one-second capture scoring.
Use the findings to improve the estimator on a development set, then rerun with a
new prespecified seed as held-out validation. Do not tune and report on the same
study as though it remained an independent test.
