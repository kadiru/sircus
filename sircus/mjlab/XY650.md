# Translated bounce-plane XY study

This development experiment moves the board center and bucket together. It keeps
the exact original650mm horizontal board-to-bucket vector, including bearing,
while changing their placement relative to the two fixed arm bases. Each query
has explicit board/bucket coordinates; it is a new family of layouts, not a
relabeling or improved result for the earlier fixed-XY scene.

The board300×200×5mm, ball, arm spacing, contact materials and frozen simulated
contact calibration are unchanged. Bucket175mm remains a reported height of
uncertain meaning; the existing175mm interior plus8mm base approximation stays
explicit. Inner177/150mm and outer200/158mm taper dimensions remain unchanged.

## Frozen request budget

- Nine translations: ΔX−10/0/+10mm × ΔY+40/+60/+80mm, applied identically to
  board center and bucket XY. Release XY remains vertically over board center.
- At each translation, H360/380/400mm × tilt26/28/30° × gap390/410/430mm:
  243 coarse requests at64 substeps. Tilt is from horizontal, facing the bucket.
  Gap is ball-bottom clearance above the configured board-center plane.
- Nine translated copies of the old380mm/28°/386.8mm recipe, plus one exact
  unshifted reference. Total253 coarse requests, all unique configured targets.
- Three unique native-valid targets receive27 H±5mm/T±0.5°/G±5mm refinements
  each, including centers: maximum81 requests. XY stays fixed within refinement.
- Up to five unique targets across coarse/refinement receive three nominal
  repeats at64 and128 substeps, preserving their exact selected joint branches:
  maximum30 verification requests.
- Original positive/negative controls retain their historical poses and exact
  joints. Three nominal copies each at64/128 precede search and repeat after it:
  24 control requests. Search opens only after clean positive3/3 and valid
  negative0/3 at both resolutions, with valid physics and oracle agreement.
- Maximum388 total requests. Every endpoint rejection stays in the denominator;
  there is no hidden rescue, resampling, changed calibration or extra PPO.

Fresh strict endpoint admission retains16-start/180-iteration CPU IK, full
native FK/collider checks and5mm clearance. Only mathematical role/target pools
are cached. No cheap reach sphere vetoes requests. Whole outer bucket footprint
needs5mm table margin. Exact controls/reference/verification branches retain
their existing protections; translated reference poses are solved afresh.

## Selection and scoring

Capture labels stay on the unchanged calibrated oracle: a measured board
rebound, downward whole-ball mouth entry and one continuous second inside.
Rim-assisted capture counts but stays separate from clean capture. Clean needs
the existing no-pre-entry-contact, no-partial-exit and1mm mouth-clearance rules.

New first-flight diagnostics affect only development ranking. Start at the first
measured board rebound, using the same0.01N contact,0.05m/s rebound and50ms
contact-free convention. End at the state immediately before the next measured
contact interval, including subsequent board contact, bucket, table, floor,
robot or unattributed contact. No position after that contact enters ranking.

At the first descending **ball-center** rim-plane crossing, interpolate XY and
compute minimum compiled-rim polygon clearance minus the ball radius. This is
a necessary aperture diagnostic, not whole-ball entry, clean passage or capture.
Fallback is the minimum sampled3D distance to the opening center during this
same first-flight segment. Invalid/missing/no-rebound diagnostics stay unavailable.

Rank native-valid records by clean capture, capture, diagnostic center-plane
crossing, larger signed aperture margin, smaller pre-contact distance, stable
record ID. Both refinement and verification deduplicate configured targets at
nine decimal places solely for selection; executed values never change.

Qualification requires a clean source,3/3clean at each resolution, physics and
independent oracle agreement, initial/final controls and≤5mm paired position
difference at350ms. These are nominal engineering checks, not noise robustness
or held-out policy evaluation. No policy is trained, replaced or activated.

## Evidence and execution

An immutable source snapshot binds the exact audited shallow/replay/coarse/
raised ancestors, native assets, packages, calibration, initial query/geometry
files and complete request ledger. A static scene fingerprint includes unchanged
scene/calibration/assets/scorer. Per-query fingerprints also bind explicit
values, bucket XY, distance rule and source record provenance. Execution hashes
add request identity, substeps, repeat index, requested joints and actual native
float32 initial joints. Rejections have no invented execution or flight.

Adaptive source IDs, preceding ledger bytes, geometry prefixes and new plans
freeze before each conditional phase. The independent CPU audit reconstructs
the literal translated grid, first-flight metrics/ranking, fresh endpoints,
dense scoring, timing/options, identities, controls and displayed traces.

Run only from a new frozen source/output namespace in the pinned Ubuntu
environment. The pipeline pins4090 by UUID and honors the shared scene lock;
it never signals another worker or changes4070/Isaac.

```bash
python -m sircus.mjlab.xy650_pipeline \
  --old-study OLD_SHALLOW --positive-study POSITIVE_CONTROLS \
  --positive-audit POSITIVE_AUDIT --replay-study AUDITED_REPLAY650 \
  --coarse-study AUDITED_COARSE650 --raised-study AUDITED_RAISED650 \
  --calibration-report FROZEN_CALIBRATION --verification-report FROZEN_VERIFICATION \
  --assets ASSETS --output NEW_OUTPUT --gpu-lock SHARED_4090_LOCK \
  --display EXISTING_INTERFACE_REPORT --batch 32 \
  --queue-timeout 14400 --wall-time-limit 7200
```

The additive read-only `xy650_study` panel (`#xy650Study`) shows explicit XY,
counts, controls, verification and actual saved ball-flight samples. Install its
fragment before `#clean650Study`, with CSS inline and JS in
`<script type="module">`. Existing services and historical panels remain intact.
Only exact-version complete audits with matching report/manifest bytes can
support a qualified UI label. Raw joints, poses, dense traces, caches, logs,
credentials and runtime configuration stay outside Git.

Useful later experiments are board-local impact offsets, dropper yaw/full
endpoint orientation choices to avoid reach/self-collision bottlenecks, and a
separate no-arm ballistics control to distinguish flight feasibility from arm
constraints. Each needs its own explicit protocol. Noise and further PPO wait.
Held endpoints do not validate grasping, arm transit, actuator tracking,
perception or physical deployment.
